# Subsystem health matrix

Primary decision surface for baseline `d39cfa2` (2026-09-27). Each row has exactly one primary classification. Full purpose/owner/state/storage/contracts/dependencies/consumers/coverage profiles are in [03](03-dependency-ownership-map.md); evidence IDs resolve in [02](02-current-architecture.md#evidence-index).

**A** healthy/preserve; **B** preserve + cleanup; **C** refactor behind existing contract; **D** partial rewrite of bounded internals; **E** subsystem recode; **F** provisional dead/redundant/legacy candidate. Risk means risk of migration/regression, including data loss, not a vulnerability severity. No E classification is justified. B subsystems contain strong assets but still have specific cleanup/protection needs; absence of an A row is not a claim that every module needs refactoring.

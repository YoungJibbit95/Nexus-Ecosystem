# Documentation drift

Classification is relative to implementation at `d39cfa2`, not a judgment of the author's original intent. No documentation outside this audit directory was changed or deleted. A historical plan is not authorization to perform its instructions now.

**CURRENT** means the inspected claims match current source at the stated scope. **PARTIALLY CURRENT** mixes correct guidance with gaps/outdated details. **HISTORICAL** records an earlier plan or observation. **MISLEADING** asserts current behavior that would materially misdirect implementation. **OBSOLETE** is a superseded claim or instruction. A classification does not certify every external service, release or device claim in a document.

## Canonical documentation after recovery

1. Keep `00` as this dated audit entry and `14` as the decision table. These report a baseline; they should not silently become timeless truth after implementation changes.
2. Establish a current architecture index linking one owner/contract page per subsystem. Put short local `ARCHITECTURE.md` files beside high-risk implementations, with state/storage/lifecycle invariants, consumers and exact checks.
3. Keep a single versioned data-format reference for app snapshots, Canvas planning metadata, Code local-file migration and handoff. Client READMEs/Wiki should link it rather than restate schemas independently.
4. Maintain a per-client capability/access matrix: local versus account-gated, browser versus native, implemented versus simulation, active versus planned. Explicitly document Code archive and Auto-Sync status.
5. Keep historical plans and release evidence dated and linked as history. Do not delete evidence or fabricate retroactive decisions.
6. Use future `docs/architecture/decisions/NNNN-short-name.md` ADRs with Context, Decision, Alternatives, Consequences, Migration impact and Affected contracts. The proposed target here is a recommendation, not an accepted historical ADR.

An architecture-doc change should cite source symbols and validation, just like code review. Updating a diagram without changing owners/contracts is not enough to resolve drift.

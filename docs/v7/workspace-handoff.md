# Workspace handoff and recovery

Main disk imports and Mobile runtime handoffs use acknowledged before/after recovery journals before replacing any store. The September save queues, complete persisted records, Canvas compatibility projection and startup recovery remain the persistence owners. A shared operation dialog prevents interactive edits while the application captures, journals, applies or rolls back a generation. Initial hydration must finish successfully before capture or interactive boot.

Drafts flush before capture; store patch queues drain after editor drafts. Notes and Canvas sessions invalidate synchronously after replacement so an old same-ID debounce cannot overwrite incoming content. Export captures one detached flushed generation for its runtime and loose files. Saved Notes arrays are authoritative on hydration, including known help-note IDs; initial help seeding applies only when no saved Notes collection exists.

Complete runtime version 1 retains its original root fields. Empty collections replace existing collections and remain empty after reload. Unknown compatible entity metadata is retained; navigation IDs normalize against imported collections. Loose directories have a distinct legacy policy: only present nonempty sections replace their respective collections; absent sections and their navigation stay unchanged. Recognized file read/JSON failures abort before application. Only an explicit missing-file result permits falling back from authoritative runtime.json to a loose directory. Loose Markdown/Code files do not encode all entity metadata or relationships; use runtime.json for complete cross-client fidelity.

Mobile uses a separately versioned internal `nexus-mobile-handoff-recovery` format, and persists its existing manual checkpoint through the shared save queue. A selected merge retains unselected sections and brings selected records' folder ancestor definitions without replacing unrelated local definitions. Missing links remain available for explicit repair. An interrupted operation restores the entire captured preimage before mounting interactive UI. A failed rollback retains both journal generations and freezes commands until successful startup recovery.

Run `node tools/run-persistence-browser-smoke.mjs` for the original editor/persistence checks. To include workspace handoff fault coverage, set `NEXUS_PERSISTENCE_SMOKE_STAGES` to `write,reload,handoff-main,handoff-main-reload,handoff-main-rollback-fail,handoff-main-recover,handoff-main-loose,handoff-mobile,handoff-mobile-reload,handoff-mobile-interrupt,handoff-mobile-recover,characterize-empty,empty-reload`. The synthetic browser fixture aborts real IndexedDB writes and fails their fallback, exercises all six Main store slices and four Mobile slices, and reloads the browser between recovery stages. Core transaction, selection and hydration tests run in the public core scope.

This is compensating multi-store recovery, not one native filesystem transaction. Native filesystem ports are injected in browser tests. OS crash/upgrade/device acceptance, cross-window mutation coordination and real notification delivery remain release gates. There is no destructive migration or legacy-storage deletion; reverting requires retaining recovery readers until every pending marker has been successfully recovered.
